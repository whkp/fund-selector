# 基金罗盘开发进展

**更新日期：2026-08-11**
**当前阶段：已移除运行时 Demo/Mock 基金数据，默认以 AKShare 公开参考数据驱动基金列表、详情和历史指标；PostgreSQL 持久化和周期指标 Worker 尚未开始。**

## 当前实现

仓库目前是一个 Vue 3 + Vite 前端与 FastAPI/Python API 组成的本地全栈项目。运行时不再保留嵌入式基金快照，基金列表和详情均由 AKShare 公开参考入口提供，已实现：

- 自然语言目标、筛选条件与候选排序
- 候选理由、风险/数据质量标签和适配度拆解
- 基金详情、按需读取历史 NAV 曲线、最多 4 只基金对比；历史数据不可用时显示空状态
- 本地观察列表、备注和大模型推荐 Trace
- FastAPI：健康检查、基金列表/详情/筛选/对比、风险画像、观察列表、数据质量、推荐运行、Trace 与行情状态接口
- 大模型研究推荐：服务端只执行用户明确硬约束和候选事实校验，模型在真实候选池内生成排序、理由、风险提示和追问；未配置或失败时不回退为规则推荐
- AKShare Adapter：支持基金目录 `fund_name_em()` 与开放式基金排行 `fund_open_fund_rank_em()`，Reference 模式才调用外部接口
- AKShare 历史净值接口：`fund_open_fund_info_em()` 已提供 `/api/funds/{code}/history`，Reference 模式返回真实 NAV 序列并计算 `metric-v1`
- Python 指标计算基础：已实现历史 NAV 的收益、年化收益、波动率、最大回撤和夏普计算函数
- 服务端 AI 状态：默认等待 OpenAI-compatible/Ollama 配置；`/api/ai/configure` 与 `/api/ai/reset` 在公开模式拒绝网页全局配置
- Reference/Production 运行模式：默认 Reference，标记 AKShare 公开参考数据和 LOW 信任等级

前端已通过 `npm run typecheck` 与 `npm run build`；Python API/指标/LLM Adapter/知识库已通过 14 项 pytest。观察列表、风险画像与推荐运行当前仍存储在 Python 进程内，重启服务后会重置。AKShare 的完整历史 NAV 批量同步、PostgreSQL 快照和独立 Worker 尚未完成。

## 与设计稿的差距

| 设计稿能力 | 当前状态 | 说明 |
|---|---|---|
| Vue 前端工作台 | 兼容 MVP 完成 | 已优先读取 FastAPI，仍未引入 Vue Router 或 Pinia。 |
| 基金数据与快照 | 部分完成 | 基金列表、详情和历史 NAV 均来自 AKShare；缺失的经理、规模、风险、申购等字段显示“未获取”。数据不是授权生产数据，不含 IOPV，也没有数据库落库。 |
| Python API 与 Worker | API 完成，Worker 未完成 | FastAPI 兼容接口和一次性目录刷新已完成；历史 NAV 批处理、数据库迁移和任务补偿未完成。 |
| AI 推荐工作流 | 大模型 MVP 完成 | OpenAI-compatible/Ollama HTTP Adapter、结构化 Schema、候选代码校验、Recommendation Run、Trace 和知识库协议已接入；模型只能通过服务端环境变量配置，尚无 Prompt/模型版本持久化或多步 Agent。 |
| 检索、缓存与异步更新 | 未开始 | 没有 OpenSearch、Redis、RabbitMQ、Outbox 或数据同步任务。 |
| 用户画像与观察列表持久化 | 仅进程内 | API 支持读写，服务重启后数据会重置。 |
| 可追溯推荐记录 | 仅进程内 | Recommendation Run、快照 ID 与 Trace 已返回，尚未落库、审计或脱敏。 |
| 自动化测试与部署 | 部分完成 | 14 项 Python API/指标/LLM/知识库测试、前端 typecheck/build 已通过；没有 PostgreSQL migration、CI 或生产部署。 |

因此，当前实现已具备可运行的本地研究闭环和独立的 ETF 行情参考，但**仍不构成设计稿定义的生产级全栈基金研究系统**。普通开放式基金的正式净值不是盘中实时数据，必须按披露日频接入授权/官方来源。

2026-08-09 已完成 GitHub 同类项目调研。Tushare/Streamlit 与 AKShare 项目普遍使用“基金目录或排行 -> 单基金历史净值 -> 本地指标计算 -> TTL 缓存”的模式。根据当前低并发和快速迭代目标，项目技术路线已从 Go 主后端调整为 **Vue 3 + FastAPI + AKShare + PostgreSQL + Python Worker + 受控 Agent**。完整的新设计、API 兼容策略、AKShare 适配器、数据快照和分阶段迁移路线见 [基金罗盘-项目设计文档](基金罗盘-项目设计文档.md)。原 [真实数据与公开服务改造方案](真实数据与公开服务改造方案.md) 保留作为调研记录，其中早期 Go 主后端建议已被新设计取代。

## 建议的后续开发顺序

1. 将 AKShare 单基金历史 NAV 从按请求读取改为 Worker 批量回补 20-50 只基金并保存指标快照。
2. 引入 PostgreSQL、Alembic 和快照仓库，替换当前 Python 内存 Repository。
3. 增加独立 Worker 的周期调度、重试、质量队列和指标重算。
4. 为基金列表批量计算真实历史指标，并将当前参考排序升级为可审计的 `research-score-v1`。
5. 实现用户持仓/目标仓位和仓位复核信号，再加入受控 Agent 解释。

## 2026-08-11 大模型研究与知识库接口

- 新增 `LLMService`：通过 OpenAI Chat Completions 兼容 HTTP 接口调用云端模型，也支持原生运行的 Ollama 兼容端点；API Key 仅由服务端环境变量或 `.env` 注入。
- `POST /api/recommendations/runs` 不再以 Python 关键词/评分规则生成候选排序。服务端先取得 AKShare 真实候选并执行用户明确的硬性边界，再由模型在该受限候选池内输出结构化排序、研究结论、风险提示和追问。
- 模型响应必须是 JSON，服务端验证 Schema、去重，并拒绝候选集合外的基金代码；未配置、调用失败或非法输出会明确失败，不以规则或模拟数据替代。
- 新增 `KnowledgeBase` 协议和本地 Markdown Adapter。设置 `FUND_COMPASS_KNOWLEDGE_BASE_PATH` 后，研究请求会检索匹配的经验文档并作为带来源的上下文传给模型；可在不改研究流程的情况下替换为 pgvector、Milvus 或外部 RAG。
- 新增 `GET /api/knowledge/status` 和 `POST /api/knowledge/search`，用于检查知识库接入状态和调试检索结果。
- 前端展示模型版本、模型研究结论和知识库引用数量；模型未配置时显示错误，不伪装为本地规则分析。
