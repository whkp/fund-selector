# 开源项目调研与可借鉴设计

> 调研时间：2026-09-27　范围：基金筛选 / 量化研究 / LLM 金融 Agent 方向的代表性 GitHub 开源项目。
> 目的：对照 fund-selector 现状，梳理**可借鉴**与**不宜照搬**的设计，给出落地优先级。
> 本文件为调研结论快照，具体实现以代码为准；采纳后请在 AGENTS.md 同步。

---

## 一、调研范围（8 个代表性项目）

| 项目 | 星量级 | 定位 | 对 fund-selector 的参考价值 |
|---|---|---|---|
| **microsoft/qlib** | ~46k | AI 量化研究平台 | 数据基础设施、PIT、因子表达式引擎、配置驱动 workflow |
| **OpenBB Platform** | ~40k+ | 模块化金融数据平台 | Provider/Fetcher/Router 三层、数据标准化、插件化 |
| **TauricResearch/TradingAgents** | ~80k+ | 多智能体 LLM 交易框架 | 多角色分工、多空辩论、LangGraph 状态图、决策持久化 |
| **AI4Finance/FinRobot** | ~6.5k | 多 Agent 金融分析 | 基金深度分析报告生成、基金对比 |
| **refraction-ray/xalpha** | ~2.4k | 基金定投回测（Python） | 定投回测引擎、持仓穿透（伪分散检测）、QDII 净值预测 |
| **axiaoxin-com/investool** | ~2k | 4433 法则基金筛选（Go） | 经典筛选法则、评分卡、回撤/经理维度展示 |
| **fund-morning-star-crawler** | 小众 | 晨星爬虫 | 分模块爬取（基础/季度持仓/快照/补数）的目录组织 |
| **backtrader / vnpy** | 万级 | 交易 / 回测框架 | 事件驱动回测内核（对纯研究工具偏重，选择性借鉴） |

**定位判断**：fund-selector 是「基金**研究 / 筛选**工具」，不是交易系统。
qlib / backtrader / vnpy 的重型回测内核不宜照搬；真正对口的是
**xalpha（回测 + 穿透）、investool（筛选法则）、OpenBB（数据层）、TradingAgents（Agent 编排）**。

## 二、fund-selector 现状对照

- 数据层：`AKShareProvider` + `DataRepository`（内存 TTL 缓存、目录 / NAV 落库与回收），
  雪球 / 蛋卷补数各写各的（`enrichment.py`）。
- 指标：`metrics.py` 只有单点 metric-v1（总收益 / 年化 / 波动 / 回撤 / 夏普），**无回测**。
- Agent：`agent_service.py` 是**单 agent 单循环**（tau harness，MAX_TURNS=8，5 个工具）。
- 调度：`workers/scheduler.py` **只跑一次**，无周期调度；`outbox_events` 无消费者；
  `recommendation_runs` / `recommendation_steps` 表建了未用。
- 筛选：`main.py` / `screen_funds` 是通用条件过滤，缺经典法则预设入口。
- 持仓：无持仓数据，无自选列表内部重叠检测。

## 三、可借鉴设计（按性价比排序）

### 第一梯队（对口、投入小、直接补现有短板）

**1. 4433 法则 + 评分卡（借鉴 investool）**
- 现状缺口：通用条件筛选，缺一键经典法则入口。
- 借鉴：4433（近 1 年排名前 1/4、近 2/3/5 年及今年来排名前 1/4、近 6 月前 1/3）做成
  **预设筛选模板**，前端一键触发；再叠加加权评分卡（收益 / 回撤 / 规模 / 费率 / 经理任职年限）。
- 落点：`agent_tools.py` 的 `screen_funds` 已支持多条件排序，加 `preset="4433"` 参数即可，几乎不动架构。

**2. 定投回测引擎（借鉴 xalpha）** ← **推荐首个落地**
- 现状缺口：`metrics.py` 无回测；AGENTS.md 已列为待办。
- 借鉴：给定「每周 / 每月投 X 元、跌 Y% 补仓」跑历史 NAV 出结果。
- 数据现成：`fund_nav_snapshots` + gzip 快照已有落库 NAV。
- 落点：新增 `backtest.py`（纯函数：NAV 序列 + 定投参数 → 收益曲线），
  配 `POST /api/funds/{code}/backtest`。与「非交易」边界不冲突（历史模拟，非下单）。

**3. 持仓穿透 / 伪分散检测（借鉴 xalpha）**
- 现状缺口：`enrichment.py` 补基本信息 + 回撤 + 风险等级，无持仓数据。
- 借鉴：「买 3 只基金，穿透发现前十大都重仓茅台」——检测自选列表（`watchlist.py` 已持久化）内部持仓重叠度。
- 落点：`enrichment.py` 加雪球 / 天天基金前十大重仓接口 → 新表 `fund_holding_snapshots`
  → watchlist 页面显示重叠预警。

### 第二梯队（架构升级，投入中等）

**4. Fetcher 三方法模式（借鉴 OpenBB）**
- 现状缺口：抓取 / 转换逻辑揉在一起，多数据源各写各的。
- 借鉴：`transform_query → extract_data → transform_data` 三段式 Fetcher +
  标准化数据模型（Pydantic）+ 单位归一化。
- 收益：多源（AKShare / 雪球 / 蛋卷）统一抽象后，加数据源成本骤降；
  「同指标多源冲突择优」可在数据层落地（现仅在 agent 提示词里约束）。

**5. 周期调度 + 事件消费者（补齐已知短板）**
- 现状缺口：scheduler 单次；outbox 无消费者；research 结果未落库。
- 借鉴：qlib 的 workflow「配置驱动 + 定时重算 + 结果落库」范式。
- 落点：scheduler 接 APScheduler / cron 做每日增量刷新；outbox_events 配后台消费者；
  研究结果落 `recommendation_runs` / `recommendation_steps`
  （TradingAgents 亦做 persistent decision log），让历史研究可回溯对比。

### 第三梯队（前沿，投入大，选择性）

**6. 多智能体辩论（借鉴 TradingAgents）**
- 现状：单 agent 单循环。
- 借鉴：TradingAgents 多角色（分析师 → 多空研究员辩论 → 风控 → 组合经理）。
  基金场景可简化为「多头研究员 vs 空头研究员」双视角辩论，降低单模型幻觉。
- 权衡：显著增加 LLM 调用成本与延迟（当前公网 history 已 5~9s）。
  建议仅在「深度研究」模式开，普通模式保留单 agent。扩展点现成（`agent_mode` 开关、`MAX_TURNS`）。

**7. PIT（Point-in-Time）数据视角（借鉴 qlib）**
- 现状：快照已有 `business_date`（NAV 回收判新鲜度用），但无严格「按披露时点组织、防未来数据泄露」。
- 借鉴：qlib PIT 数据库——基金季报持仓、经理变更用「当时可见」时点。
- 落点：若做回测（第 2 项），PIT 是正确性前提（否则回测作弊），设计时即带「只用截止日之前数据」约束。

## 四、不建议照搬

- **qlib 自研时序二进制存储 / 因子表达式引擎**：为海量高频股票设计；本项目日频基金、量级小，
  Neon + gzip 已够，引入反增复杂度。
- **vnpy / backtrader 事件驱动交易内核**：面向实盘下单，与「非交易系统」产品边界冲突。
- **OpenBB 完整插件市场 / entry_points 机制**：数据源仅 3 个，用不到社区插件生态；
  借鉴 Fetcher **模式**即可，不必上插件框架。

## 五、推荐落地顺序

```
第 1 步：定投回测引擎（backtest.py）        ← 价值最高、数据现成、补头号缺口
第 2 步：4433 法则预设 + 评分卡              ← 改动小、用户可感知强
第 3 步：周期调度 + outbox 消费者 + 研究落库 ← 补齐已知短板、让系统"活"起来
第 4 步：持仓穿透 / 伪分散检测              ← 差异化功能、需新数据源
第 5 步：Fetcher 三段式重构                ← 架构债，趁加数据源时一起做
第 6 步：多智能体辩论（深度模式限定）       ← 前沿，成本敏感，最后做
```
